# AZ-CP-001 Incident Investigation

## Executive summary

Microsoft Sentinel detected a successful Azure diagnostic-settings write generated by
an authorized, idempotent lab deployment. The scheduled analytics rule produced one
Medium alert and one incident. The scoped automation rule changed the incident to
Active, kept Medium severity, and added the `SOAR-Triaged` label. Investigation found no
change to the destination or any of the eight enabled log categories and confirmed that
telemetry continued afterward. The incident was closed as `BenignPositive` with the
reason `SuspiciousButExpected`.

## Investigation questions and findings

| Question | Finding |
|---|---|
| Which operation occurred? | `Microsoft.Insights/diagnosticSettings/write` |
| Was it successful? | Yes; the Success event exists in both the Activity Log and `AzureActivity` |
| Was the target approved? | Yes; it was the existing subscription Activity Log export |
| Did categories or destination change? | No; all eight categories and the dedicated workspace destination remained unchanged |
| Was the action authorized? | Yes; it was generated by the documented lab validation deployment |
| Did telemetry continue? | Yes; the operation itself reached `AzureActivity` and Sentinel created an alert |
| Did SOAR execute? | Yes; the incident became Active/Medium with the `SOAR-Triaged` label |

## Baseline

- Diagnostic setting: `sentinel-lab-azure-activity`
- Destination: dedicated Azure Cloud Security Lab workspace
- Enabled categories: Administrative, Security, ServiceHealth, Alert,
  Recommendation, Policy, Autoscale, and ResourceHealth
- Expected controlled action: idempotent redeployment of the identical configuration
- Expected impact: no category or destination change and no telemetry interruption

## Disposition

- Status: Closed
- Classification: Benign positive
- Reason: Suspicious but expected
- Severity: Medium
- Alert count: 1
- Automation evidence: `SOAR-Triaged`

The test analytics and automation rules were disabled immediately after validation to
prevent duplicate incidents from the one-hour test lookback. Their IaC remains in the
repository for repeatable demonstrations.

## Privacy

Caller identity, IP address, subscription ID, tenant ID, workspace ID, resource ID,
incident ID, alert ID, authorization data, and correlation ID were used only in the
private investigation and are excluded from committed evidence.
